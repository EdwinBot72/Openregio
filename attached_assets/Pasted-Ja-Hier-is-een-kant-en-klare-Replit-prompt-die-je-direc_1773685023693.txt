## Replit prompt — complete QA/testaanpak voor OpenRegio

```text
Act like a senior QA Lead, Test Manager, and web test automation engineer with strong experience in enterprise SaaS, payments, role-based access control, onboarding flows, and responsive React applications.

Your task is to fully analyze, test, and prepare an executable QA package for the current app in this Replit project.

You must inspect the actual codebase first, infer the app architecture and core flows from the code, then produce a complete and concrete QA/testing package that can be used immediately by a QA team and developers.

The app is OpenRegio, a responsive web platform for entrepreneurs with public landing pages, account flows, paid memberships, dashboard tools, role-based access, onboarding, profile management, admin features, and integrations.

Work step by step.

## Main goal
Create a practical, release-focused QA deliverable based on the actual code in this Replit project, not generic assumptions.

## What you need to do

### 1. Inspect the codebase first
Read the code and identify:
- app type and architecture
- frontend stack
- backend stack
- routes/pages
- auth flows
- role models
- payment flows
- admin features
- API integrations
- upload/document flows
- onboarding flows
- core business-critical user journeys
- likely risk areas

Summarize these findings clearly.

### 2. Build a QA context summary
Describe:
- app goals
- main user roles
- critical business flows
- data flows
- external dependencies
- sensitive/PII data
- biggest product and release risks

### 3. Create a test strategy
Define:
- smoke testing
- regression testing
- end-to-end testing
- exploratory testing
- non-functional testing

Include:
- priority by business risk
- entry criteria
- exit criteria
- release blockers

### 4. Define scope
Create clear sections:
- In scope
- Out of scope
- Assumptions

### 5. Create a test coverage matrix
Make a matrix:
Features x Test Types

Include these test types where relevant:
- functional
- usability
- accessibility
- performance
- security
- compatibility

### 6. Write concrete test cases
Generate at least 40 detailed test cases.

Each test case must include:
- ID
- title
- preconditions
- steps
- test data
- expected result
- priority (P0/P1/P2)

You must include:
- happy paths
- negative tests
- edge cases
- authorization tests
- payment tests
- API failure tests
- retry/idempotency tests
- validation tests
- responsive/mobile tests

### 7. Add exploratory testing charters
Create 10 exploratory testing charters for 45-minute sessions.

### 8. Define non-functional checks
Make concrete, measurable checks for:
- performance
- security/privacy
- accessibility
- reliability/resilience

Specifically include:
- OWASP-style access control risks
- XSS/input validation
- file upload safety
- session/auth weaknesses
- retry/timeouts
- offline/slow network behavior
- WCAG basics on critical flows

### 9. Automation advice
Recommend:
- top 10 flows to automate first
- which should be UI vs API tests
- suggested test suite structure

Prefer modern practical tooling suitable for this stack.

### 10. Bug reporting package
Provide:
- a bug report template
- one fully written example bug based on a realistic risk in this codebase

### 11. Release readiness checklist
Create a short go / no-go checklist with measurable thresholds.

## Important instructions
- Base everything on the actual project code
- Do not ask me follow-up questions
- If information is missing, make explicit assumptions and continue
- Be concrete, not vague
- Be release-focused and risk-based
- Prioritize what would actually break production or damage trust
- Highlight security/privacy/access-control issues aggressively
- Focus on what matters most for an MVP or real release

## Output format
Return the result in Markdown with these sections:

# QA Context Summary
# Risks
# Test Strategy
# Scope
# Coverage Matrix
# Detailed Test Cases
# Exploratory Charters
# Non-Functional Checks
# Automation Recommendations
# Bug Reporting
# Release Readiness

## Extra instruction
At the end, add a final section:

# Suggested Immediate Smoke Pack

This must contain the 10 most critical tests to run right after deployment.

Now inspect the codebase and generate the full QA package.
```

## Kortere versie voor Replit AI

Als Replit moeite heeft met een te lange prompt, pak deze:

```text
Act like a senior QA Lead and web test automation engineer.

Inspect this entire Replit codebase first and infer the real app structure, roles, flows, integrations, and risks from the code.

Then create a complete QA package in Markdown for this app, including:

1. QA context summary
2. Main risks
3. Test strategy
4. Scope (in/out/assumptions)
5. Coverage matrix (features x functional/usability/accessibility/performance/security/compatibility)
6. At least 40 detailed test cases with ID, preconditions, steps, test data, expected result, and priority P0/P1/P2
7. 10 exploratory testing charters
8. Non-functional checks for performance, security/privacy, accessibility, and reliability
9. Automation recommendations (top 10 to automate, UI/API split, suite structure)
10. Bug report template + example bug
11. Release readiness checklist
12. Immediate smoke pack after deployment

Important:
- Use the actual codebase, not generic assumptions
- Do not ask follow-up questions
- If something is unclear, make explicit assumptions and continue
- Focus on production risks, access control, payments, onboarding, uploads, auth, and release blockers
- Be concrete and executable
```

## Slimste manier om hem in Replit te gebruiken

Plak eerst de lange prompt.
Als Replit te algemeen blijft, stuur er meteen achteraan:

```text
Now go deeper. Read the actual routes, middleware, auth logic, admin routes, payment/webhook logic, onboarding logic, and file upload handling from the codebase. Then revise the QA package so it matches the real implementation more precisely.
```

En daarna nog deze:

```text
Now turn the test cases into a practical QA execution table grouped by:
- Smoke
- Regression
- E2E
- Security/Auth
- Payments
- Admin
- Mobile/Responsive
```
