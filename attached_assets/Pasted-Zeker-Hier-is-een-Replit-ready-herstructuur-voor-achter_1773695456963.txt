Zeker. Hier is een **Replit-ready herstructuur** voor achter de login.

Ik hou het strak:

* nieuwe sidebar-structuur
* vaste paginatitels
* logische dashboardvolgorde
* één bron van waarheid voor labels
* direct bruikbare TypeScript-config

---

# 1. Wat nu kapot voelt

In jouw code zitten nu dit soort breuken:

* **Nieuw verzoek** → pagina heet **Juridische Instrumenten**
* **Mijn verzoeken** → route is **/woo-bibliotheek**
* **Documenten & dossiers** → route is **/woo-bot**
* **Zichtbaarheidsbeheer** → route is **/pro/visibility-settings**
* **RegioBot** → begint voor niet-Pro met **Extra tools beschikbaar**

Dus de gebruiker klikt op een simpele taak, maar landt in interne producttaal. Dat maakt het rommelig.

# 7. Wat je meteen moet hernoemen in bestaande pagina’s

## A. `/woo-wizard.tsx`

Nu:

* **Juridische Instrumenten**
* **Wat zijn Juridische Instrumenten?**
* **Bevoegdheidsscan (WOO-verzoek)**

Moet worden:

* **Nieuw Woo-verzoek**
* **Wat is een Woo-verzoek?**
* **Woo-verzoek opstellen**

### Vervang dit:

```tsx
<h1 className="text-3xl font-bold mb-2">Juridische Instrumenten</h1>
```

### Door dit:

```tsx
<h1 className="text-3xl font-bold mb-2">Nieuw Woo-verzoek</h1>
<p className="text-muted-foreground">
  Stel stap voor stap een nieuw Woo-verzoek op en exporteer direct je concept.
</p>
```

---

## B. `/woo-bibliotheek.tsx`

Als dit feitelijk overzicht is van verzoeken/documenten:

* noem het **Mijn documenten**
* niet bibliotheek

---

## C. `/woo-bot.tsx`

Als dit een AI-/documenttool is:

* noem het **Document-assistent**
* niet “Woo Bot” tenzij het echt alléén om Woo gaat

---

## D. `/pro-visibility-settings.tsx`

Nu technisch.
Maak het:

* **Privacy & zichtbaarheid**

---

## E. `/regiobot.tsx`

Laat altijd bovenaan gewoon:

* **RegioBot**

Niet eerst “Extra tools beschikbaar” als hoofdkop. Dat voelt als upsell-scherm, niet als productscherm.

# 8. Nieuwe `AppSidebar.tsx` aanpak

Je huidige `AppSidebar.tsx` bevat harde arrays. Dat is precies waarom alles uit elkaar kan lopen.

Maak het data-driven.

## Vervang de losse `navSections` door imports:

```tsx
import { APP_NAV, ACCOUNT_NAV } from "@/config/navigation";
```

En render op basis van die config.

# 9. Slimme UX-regel voor heel OpenRegio

Gebruik deze regel overal:

## Eén taak = één naam

Dus:

* menu = **Nieuw Woo-verzoek**
* pagina = **Nieuw Woo-verzoek**
* dashboardkaart = **Nieuw Woo-verzoek**
* button = **Nieuw Woo-verzoek starten**

Niet:

* menu = Nieuw verzoek
* pagina = Juridische Instrumenten
* knop = Bevoegdheidsscan

Dat is exact de chaos die je nu voelt.

# 11. Kort verdict

Wat jij voelt klopt volledig:
**de login-omgeving mist nu één dominante structuurlaag.**

Niet omdat er te veel features zijn, maar omdat:

* labels niet consistent zijn
* interne termen lekken naar de UX
* routes en schermtitels elkaar tegenspreken

Deze set hierboven fixt dat zonder dat je hele app opnieuw hoeft te bouwen.

Ik kan dit ook nog voor je omzetten naar een **kant-en-klare patch voor `AppSidebar.tsx` + `dashboard.tsx` + `woo-wizard.tsx`**.
