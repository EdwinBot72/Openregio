Hier is je **live go / no-go checklist**. Gewoon afvinken.

# OpenRegio live checklist

## 1. Basis infra

**Moet groen zijn**

* [ ] `npm run check` geeft geen errors
* [ ] `npm run build` slaagt
* [ ] `npm run start` start zonder crash
* [ ] `DATABASE_URL` wijst naar een echte werkende Postgres
* [ ] `SESSION_SECRET` staat ingesteld en is lang/random
* [ ] domein staat goed gekoppeld
* [ ] HTTPS werkt

**No-go als**

* app niet boot
* database niet bereikbaar is
* sessies niet werken

---

## 2. Database

**Check**

* [ ] alle tabellen bestaan
* [ ] migrations of `db:push` zijn uitgevoerd
* [ ] seed draait niet kapot bij startup
* [ ] app kan lezen en schrijven in DB

**Test**

* [ ] maak een testuser aan
* [ ] kijk of user echt in DB komt
* [ ] wijzig iets in profiel
* [ ] check of wijziging bewaard blijft

**No-go als**

* inserts falen
* seed startup blokkeert
* users of subscriptions niet worden opgeslagen

---

## 3. Auth

**Test functioneel**

* [ ] registreren werkt
* [ ] inloggen werkt
* [ ] uitloggen werkt
* [ ] protected pagina zonder login blokkeert goed
* [ ] protected pagina met login opent goed
* [ ] pagina refresh houdt sessie vast
* [ ] sessie verloopt niet direct onterecht
* [ ] refresh-token flow werkt bij 401

**No-go als**

* users spontaan uitloggen
* login wel lukt maar protected routes niet
* refresh-token loop of white screen ontstaat

---

## 4. Profiel / user data

**Check**

* [ ] avatar / profielfoto laadt zonder fout
* [ ] profielgegevens worden goed opgehaald
* [ ] profiel opslaan werkt
* [ ] sidebar toont juiste naam/foto/rol

**No-go als**

* profielroute 500 geeft
* sidebar crasht door missende uservelden

---

## 5. Mollie betalingen

**Test met testkey eerst**

* [ ] checkout kan gestart worden
* [ ] je wordt doorgestuurd naar Mollie
* [ ] return URL komt terug op juiste pagina
* [ ] payment status wordt correct opgehaald
* [ ] mislukte betaling geeft nette foutstatus
* [ ] geannuleerde betaling breekt de app niet

**Webhook**

* [ ] webhook endpoint is publiek bereikbaar
* [ ] Mollie webhook wordt ontvangen
* [ ] payment/subscription status wordt opgeslagen in DB
* [ ] dubbele webhook veroorzaakt geen dubbele records
* [ ] verkeerde webhook payload crasht de app niet

**No-go als**

* checkout start maar niets terugschrijft
* webhook niet aankomt
* betaalde user geen juiste status krijgt

---

## 6. Abonnementen

**Check**

* [ ] subscription wordt aangemaakt
* [ ] actieve status wordt correct opgeslagen
* [ ] verlopen/geannuleerd status wordt correct verwerkt
* [ ] rechten in app volgen subscription status

**No-go als**

* betaald account geen toegang krijgt
* gestopte betaling toch toegang houdt terwijl dat niet hoort

---

## 7. E-mail / onboarding

**Check**

* [ ] Postmark key staat goed
* [ ] onboarding mail wordt echt verstuurd
* [ ] from-address is correct
* [ ] links in mails werken
* [ ] first-login flow werkt

**No-go als**

* app zegt “mail verzonden” terwijl dat niet zo is
* onboardingflow hangt op mailfouten

---

## 8. Frontend basis

**Check**

* [ ] home laadt snel
* [ ] geen witte pagina’s
* [ ] geen console spam met errors
* [ ] mobiel bruikbaar
* [ ] navigatie klopt
* [ ] alle hoofdknoppen werken
* [ ] 404 pagina werkt
* [ ] error states tonen nette feedback

**No-go als**

* hoofdflow afhankelijk is van kapotte knop
* console vol staat met runtime errors

---

## 9. Backend / API sanity

**Check**

* [ ] API routes geven geen 500 zonder reden
* [ ] invalid input geeft nette 4xx response
* [ ] auth routes geven juiste statuscodes
* [ ] logs tonen geen secrets
* [ ] rate-limit of basisbescherming is er als nodig

**No-go als**

* server sensitive data logt
* routes intern stacktraces lekken naar client

---

## 10. Env-vars

Minimaal scherp hebben:

* [ ] `DATABASE_URL`
* [ ] `SESSION_SECRET`

Waarschijnlijk ook nodig:

* [ ] `MOLLIE_API_KEY`
* [ ] `POSTMARK_API_KEY`
* [ ] eventuele app/base URL
* [ ] webhook/return URLs live goed gezet

**No-go als**

* live URLs nog naar localhost wijzen
* testkeys in productie staan zonder bedoeling

---

## 11. Domein / callbacks

**Check**

* [ ] login callback URLs kloppen
* [ ] Mollie return URL klopt
* [ ] Mollie webhook URL klopt
* [ ] mails gebruiken live domein
* [ ] mixed content issues zijn er niet

**No-go als**

* één callback nog op dev/staging staat

---

## 12. Beheer / herstel

**Check**

* [ ] je kunt een admin account gebruiken
* [ ] er is een manier om logs te lezen
* [ ] je kunt database backuppen
* [ ] je kunt snel rollbacken naar vorige versie

**No-go als**

* er geen recovery pad is na live fout

---

# Keiharde live testflow

Doe deze exact, dan weet je of je echt safe zit:

## Flow A: gebruiker

* [ ] open site
* [ ] registreer nieuwe gebruiker
* [ ] bevestig dat user in DB staat
* [ ] log in
* [ ] open protected pagina
* [ ] refresh browser
* [ ] sessie blijft actief

## Flow B: betaling

* [ ] klik abonnement / betaal
* [ ] ga naar Mollie test checkout
* [ ] rond betaling af
* [ ] kom terug op success page
* [ ] controleer DB status
* [ ] controleer webhook logs
* [ ] controleer toegang in app

## Flow C: foutpad

* [ ] annuleer betaling
* [ ] check nette foutmelding
* [ ] useraccount blijft heel
* [ ] geen halve subscription rommel in DB

## Flow D: mail

* [ ] onboarding mail komt aan
* [ ] link werkt
* [ ] geen broken template

---

# Mijn go / no-go regel

**GO**
als deze 4 groen zijn:

1. auth werkt
2. betaling werkt
3. webhook schrijft correct weg
4. DB en mailflow breken niet

**NO-GO**
als 1 van die 4 nog twijfelachtig is

---

# Advies voor jou

Zet hem eerst live als:

* **staging** of
* **soft launch**

Niet meteen hard adverteren of klanten erop sturen voordat die complete testflow groen is.

Wil je, dan maak ik hier direct ook een **ultrakorte Replit deployment checklist** van met exacte volgorde: env-vars → db push → start → testbetalingen.
