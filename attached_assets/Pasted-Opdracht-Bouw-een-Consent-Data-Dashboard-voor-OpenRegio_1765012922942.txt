Opdracht: Bouw een Consent & Data Dashboard voor OpenRegio (Replit-ready)
1. Doel van de opdracht

Bouw een kleine webapp (MVP) waarin een ingelogde ondernemer:

Zijn/haar profieldata kan zien.

Per onderdeel kan bepalen:

wat zichtbaar is,

voor wie (publiek / alleen leden / alleen regio / privé).

Zijn/haar data kan exporteren (JSON-download).

Zijn/haar account en data kan laten verwijderen (soft delete).

Dit moet draaien op Replit en later koppelbaar zijn aan het grotere OpenRegio-platform.

2. Stack & randvoorwaarden

Voorkeursstack (maar mag equivalent):

Backend: Node.js + Express

Database: SQLite (of Postgres via hosted DB)

Frontend: simpele server-side views (EJS / Pug) of een lichte React frontend

Auth: simpele username + password login (hashed password)

Randvoorwaarden:

Code moet op Replit kunnen draaien zonder extra hacks.

.env gebruiken voor secrets.

Project moet via npm start te runnen zijn.

3. Kernfunctionaliteiten
3.1. Account & login

Registreer ondernemer:

velden: email, password, company_name, region, phone, created_at.

Login-systeem:

hash wachtwoord (bijv. bcrypt).

simpele sessies (cookie + express-session).

Alleen ingelogde gebruikers hebben toegang tot het dashboard.

3.2. Profiel & zichtbaarheid

Elke ondernemer heeft een profiel met:

company_name

description

address

phone

website

region

En per veld een visibility-setting:

PUBLIC – zichtbaar voor iedereen

MEMBERS – zichtbaar voor ingelogde leden

REGION_ONLY – zichtbaar voor leden in dezelfde regio

PRIVATE – niet zichtbaar voor andere gebruikers

UI-vereisten:

Eén dashboard-pagina /dashboard

Tabel/kaartje met:

veldnaam

huidige waarde

dropdown met de visibility setting

Opslaan-knop → update in database

3.3. Consent-log

Elke keer dat een ondernemer een zichtbaarheid wijzigt:

Log in tabel consent_log:

user_id

field_name

old_visibility

new_visibility

changed_at

In het dashboard:

Extra sectie “Historie” met laatste 10 wijzigingen:

datum/tijd

veld

van → naar

3.4. Data-export (AVG / natuurrecht vibes)

Knop: “Download mijn data”

Route: GET /me/export

Response: JSON download met:

{
  "profile": { ... },
  "visibility": { ... },
  "consent_log": [ ... ]
}


UI:

Knop op dashboard: “Exporteer mijn data (JSON)”.

3.5. Account-/dataverwijdering

Knop: “Verwijder mijn account en data”

Flow:

Bevestigingsscherm: “Weet je zeker dat je je account wilt verwijderen? Dit is niet terug te draaien.”

Bij bevestiging:

Markeer users.deleted_at met timestamp.

Verwijder/zets anoniem alle gerelateerde data OF markeer als verwijderd.

Log gebruiker uit.

Na verwijderen:

redirect naar pagina met tekst “Je account is verwijderd.”

4. Datamodel (voorstel)

Tabel: users

id (PK)

email (unique)

password_hash

company_name

description

address

phone

website

region

created_at

deleted_at (nullable)

Tabel: field_visibility

id (PK)

user_id (FK → users.id)

field_name (string, bijv. "phone", "address")

visibility (enum: PUBLIC / MEMBERS / REGION_ONLY / PRIVATE)

Tabel: consent_log

id (PK)

user_id (FK)

field_name

old_visibility

new_visibility

changed_at

5. API-routes

Auth

GET /register – formulier

POST /register – maak user aan

GET /login – login-formulier

POST /login – inloggen

POST /logout – uitloggen

Dashboard

GET /dashboard

Haalt profiel + visibility + laatste 10 consent_log items op.

POST /dashboard/visibility

Body: { field_name, visibility }

Update visibility, log wijziging in consent_log.

Data

GET /me/export

POST /me/delete

6. Security & kwaliteit

Wachtwoord hashing (bcrypt).

Input valideren (geen lege velden waar dat niet mag, correcte enums).

Basic CSRF-protectie (of minimaal een token check).

Geen secrets hardcoded in code.

Logische checks: een user mag alleen eigen data zien/wijzigen.

8. Acceptatiecriteria (wanneer is dit “done”?)

✅ Een nieuwe ondernemer kan registreren, inloggen en een profiel invullen.

✅ Per veld is visibility in te stellen en wordt dit opgeslagen.

✅ Wijzigingen in visibility worden gelogd en zijn zichtbaar in de historie.

✅ De ondernemer kan zijn data als JSON downloaden.

✅ De ondernemer kan account + data verwijderen.

✅ Project draait op Replit met één klik op “Run”.
