Top. Hier is je **bouwplan** (MVP → v1) dat je letterlijk kunt afvinken in Replit.

## Doel van de MVP

**Ondernemer logt in → doet 5-min scan → krijgt score + 3 blockers + 2 leverage → kan 1-pager downloaden.**
Alles regionaal, alles simpel, alles snel.

---

## Fase 0 — Project setup (1 uur)

**Replit project: Full-stack**

* `/client` = React + Vite
* `/server` = Node + Express
* Postgres (Neon/Supabase) via `DATABASE_URL` in Secrets

**Secrets**

* `DATABASE_URL`
* `APP_URL` (je domein/replit url)
* `JWT_SECRET` (later) of `LOGIN_CODE_SECRET`

## Fase 1 — UX flow (build-first, design later)

### Pagina’s (routes)

1. `/` **Landing**

   * H1: “Regio-analyse”
   * Sub: “Korte scan: wat blokkeert groei, waar zit leverage.”
   * CTA: **Start scan**
2. `/login`

   * Email + “Stuur code”
   * Code invullen (6 digits)
3. `/scan`

   * 8 vragen, 1 per scherm
   * progressbar `x/8`, “± 4 min”
4. `/result/:scanId`

   * Regio-score (0–100)
   * 3 blockers
   * 2 leverage
   * 3 CTA knoppen:

     * Bekijk matches (coming soon)
     * Activeer regio-structuur (upsell)
     * Download 1-pager (PDF)
5. `/download/:scanId` (of knop die API hit)

**UX regels**

* 1 vraag per scherm (minder stress)
* Alleen radio buttons (geen tekstvelden)
* Autosave na elke vraag

## Fase 2 — Scan inhoud (de 8 vragen)

Je splitst in 4 domeinen (2 vragen per domein):

### A) Zichtbaarheid (regionaal)

1. Sta je correct op Google/Maps + consistente NAW?
2. Kom je binnen via “regio + dienst” zoekopdrachten?

### B) Netwerk / doorverwijzing

3. Krijg je structureel werk via andere ondernemers?
4. Verwijs jij structureel werk door binnen de regio?

### C) Afhankelijkheid / instroom

5. Komt >50% van je leads via één kanaal/platform?
6. Heb je een eigen “vaste instroom” (klanten/partners/herhaal)?

### D) Back-to-basic / continuïteit

7. Kun je draaien bij storing (bereikbaarheid, betaling, planning)?
8. Heb je je basis juridisch/administratief op orde (factuur, KvK, btw, algemene voorwaarden/afspraken)?

Antwoorden: **Ja / Soms / Nee** → scores 2/1/0.

---

## Fase 3 — Scoring engine (server-side)

### Output die je altijd maakt

* `score_total` (0–100)
* `domain_scores` (A/B/C/D)
* `blockers` = laagste 3 issues (met label + 1 actie)
* `leverage` = hoogste 2 hefboom-kansen (met label + 1 actie)

### Hoe je dat simpel doet

* Per domein: max 4 punten (2 vragen × 2)
* Totaal max 16 punten → normaliseer naar 100:

  * `score = round((total_points / 16) * 100)`

**Blockers mapping** (voorbeeld)

* Lage B-score → “Geen regio-doorverwijzing → werk lekt weg”
* Lage C-score → “Te afhankelijk van 1 kanaal → fragiel”
* Lage D-score → “Geen fallback → paniek bij uitval”

**Leverage mapping**

* Hoge A-score → “Zichtbaarheid is al sterk → schaal via regio-structuur”
* Hoge B-score → “Netwerk-ready → matches leveren direct omzet”

## Fase 4 — Database (minimaal maar future-proof)

### Tabellen

* `users`: id, email, created_at
* `login_codes`: email, code_hash, expires_at (optioneel)
* `scans`: id, user_id, region, sector, created_at, completed_at
* `answers`: id, scan_id, question_key, value
* `results`: scan_id, score_total, domain_scores_json, blockers_json, leverage_json

**Waarom zo?**

* Alles herbruikbaar: later kun je “trends”, “sector benchmark”, “regio heatmap” toevoegen zonder refactor.

---

## Fase 5 — API endpoints (MVP)

**Auth**

* `POST /api/auth/request-code` (email → code)
* `POST /api/auth/verify-code` (email+code → session token)

**Scan**

* `POST /api/scans` (maakt scanId + region/sector)
* `POST /api/scans/:id/answer` (autosave 1 antwoord)
* `POST /api/scans/:id/complete` (triggert scoring + result opslag)

**Result**

* `GET /api/scans/:id/result` (score + blockers + leverage)
* `GET /api/scans/:id/pdf` (later of v1)

## Fase 7 — “Activeer regio-structuur” (upsell zonder cringe)

Op resultpagina toon je modules als tegels:

* **RegioMarkt** (doorverwijzing & afspraken)
* **Zichtbaarheid** (NAW, reviews, regio vindbaarheid)

Elke tegel:

* 1 zin + 1 uitkomst
* knop: “Aanvragen” / “Meedoen”
