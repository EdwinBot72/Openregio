Dus als “account aanmaken” faalt, is het meestal één van deze 3:

DATABASE_URL ontbreekt / DB down
→ register geeft 500, want storage.createUser kan niks wegschrijven.

→ register lijkt te slagen, maar je “bent niet ingelogd” daarna.

Frontend route/redirect mismatch
→ je wordt naar /dashboard gestuurd, maar auth state is niet gezet/gelezen zoals je verwacht.

Meest voorkomende op Replit: DATABASE_URL niet gezet.

De 5 grootste “gekke dingen” die ik zie
1) DB + migraties: dit is nu de #1 reden dat registratie faalt

Je server gooit direct een error als DATABASE_URL ontbreekt (db/index.ts).

En je runMigrations() doet ALTER TABLE op tabellen die op een verse DB nog niet bestaan → dan knalt de server bij start.

Fix in Replit (must-do):

Secrets: DATABASE_URL zetten

Eenmalig draaien: npm run db:push
(maakt tabellen uit shared/schema.ts)

Daarna pas npm run dev

Zonder dit: register/login blijft random kapot.

2) Brief uploaden / RegioBot docs bestaan, maar staan Pro-only

Deze endpoints zijn “aanwezig”, maar in praktijk dicht:

/api/regiobot/upload → requirePro

/api/rag/documents → requirePro

/api/rag/ask → requirePro

Dus ja: je kan geen brieven uploaden als:

je account niet werkt

of je plan niet Pro is

of je pro-status niet goed gezet wordt

MVP-keuze: Basic = 1 upload / Pro = onbeperkt.
(Anders voelt je product nep.)

3) WOO generator endpoint bestaat, maar werkt alleen met OpenAI key

POST /api/woo/generate is public, maar:

Zonder OPENAI_API_KEY geeft hij 503 (“AI-config niet voltooid”).

Fix: Secret OPENAI_API_KEY zetten.

Nog iets: dit endpoint is public → kan misbruikt worden (kost geld).
Later: rate limit of requireAuth.

4) Je hebt dubbele auth/middleware spul (verwarrend onderhoud)

Ik zie twee requirePro implementaties:

server/jwtAuth.ts

server/middleware/auth.ts

Dat is asking for bugs (“waarom werkt het hier wel en daar niet?”).

Fix: kies één auth pad (jwtAuth) en kill/stop gebruik van de andere.
