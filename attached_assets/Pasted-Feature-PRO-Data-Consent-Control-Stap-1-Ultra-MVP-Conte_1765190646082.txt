Feature: PRO “Data & Consent Control” (Stap 1 – Ultra MVP)

Context
Er is al een backend met:

users-tabel (company_name, phone, address, website, description, region, plan)

login + req.user

profielpagina /profile/:id

Doel
PRO-leden moeten per profielveld kunnen instellen wie het mag zien:

PUBLIC

MEMBERS

REGION_ONLY

PRIVATE

En deze settings moeten worden gebruikt bij het tonen van profielen.

1. Database

Taak:

Voeg in users een kolom toe:

ALTER TABLE users
ADD COLUMN visibility_settings TEXT; -- JSON string


Structuur van de JSON:

{
  "company_name": "PUBLIC",
  "phone": "MEMBERS",
  "address": "REGION_ONLY",
  "website": "PUBLIC",
  "description": "MEMBERS"
}


Defaults:

Als visibility_settings leeg of ongeldig is → bovenstaande defaults gebruiken.

Als een key ontbreekt → behandelen als PUBLIC (of dezelfde default-set toepassen).

2. Business rules

Implement een helper:

function canViewField(viewer, owner, fieldVisibility) {
  if (viewer && viewer.id === owner.id) return true; // eigenaar ziet alles

  switch (fieldVisibility) {
    case 'PUBLIC':
      return true;
    case 'MEMBERS':
      return !!viewer;
    case 'REGION_ONLY':
      return !!viewer && viewer.region === owner.region;
    case 'PRIVATE':
      return false;
    default:
      return true; // fallback PUBLIC
  }
}

3. Routes
3.1 Middleware
function requireAuth(req, res, next) {
  if (!req.user) return res.redirect('/login');
  next();
}

function requirePro(req, res, next) {
  if (!req.user || req.user.plan !== 'PRO') {
    return res.status(403).send('PRO-lidmaatschap vereist');
  }
  next();
}

3.2 GET /pro/visibility-settings

Alleen toegankelijk voor PRO via requireAuth + requirePro.

Haal visibility_settings van req.user.

Parse JSON, merge met defaults.

Render template pro/visibility-settings met:

user

settings

options = ['PUBLIC','MEMBERS','REGION_ONLY','PRIVATE']

3.3 POST /pro/visibility-settings

Body keys: company_name, phone, address, website, description.

Valideer: value ∈ ['PUBLIC','MEMBERS','REGION_ONLY','PRIVATE'].

Sla alles op als JSON in users.visibility_settings van de ingelogde user.

Redirect terug naar /pro/visibility-settings?updated=1.

4. UI (één pagina)

Template pro/visibility-settings:

Tabel met rijen:

Veld | Waarde | select met opties

Eén Opslaan-button.

Pseudovoorbeeld:

<form method="POST" action="/pro/visibility-settings">
  <table>
    <tr><th>Veld</th><th>Waarde</th><th>Zichtbaarheid</th></tr>

    <!-- herhalen per veld -->
    <tr>
      <td>Bedrijfsnaam</td>
      <td><%= user.company_name %></td>
      <td>
        <select name="company_name">

            <option value="<%= opt %>" <%= settings.company_name === opt ? 'selected' : '' %>><%= opt %></option>

        </select>
      </td>
    </tr>
    <!-- etc. voor phone, address, website, description -->

  <button type="submit">Opslaan</button>
</form>

5. Profielpagina aanpassen

Route /profile/:id:

Haal owner uit DB.

Parse owner.visibility_settings + merge defaults.

Maak helper canView(fieldName) die canViewField(viewer, owner, visibility[fieldName]) gebruikt.

In de template per veld:

Telefoon:
<%= canView('phone') ? owner.phone : 'Niet zichtbaar voor jou' %>

✔ Acceptatiecriteria

PRO-user kan /pro/visibility-settings openen.

Dropdowns werken en slaan op in users.visibility_settings.

/profile/:id toont/maskeert velden o.b.v. visibility-regels.

Niet-PRO users krijgen 403 op /pro/visibility-settings.
