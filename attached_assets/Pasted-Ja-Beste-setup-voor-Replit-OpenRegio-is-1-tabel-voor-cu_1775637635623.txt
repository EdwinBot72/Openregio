* **1 tabel voor cursus-items**
* **1 tabel voor gebruikersvoortgang**
* optioneel **1 tabel voor sectors of plans**

Hier is de strakste basis.

## 2. Database-structuur voor OpenRegio

Als je dit netjes wilt bouwen in PostgreSQL met Drizzle op Replit:

### tabel `daily_courses`

```sql
CREATE TABLE daily_courses (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  title TEXT NOT NULL,
  slug TEXT NOT NULL UNIQUE,
  category TEXT NOT NULL,
  sector TEXT NOT NULL DEFAULT 'algemeen',
  plan TEXT NOT NULL DEFAULT 'basis',
  status TEXT NOT NULL DEFAULT 'draft',
  posted_at TIMESTAMPTZ NOT NULL,
  expires_at TIMESTAMPTZ NOT NULL,
  minutes INTEGER NOT NULL,
  goal TEXT NOT NULL,
  action TEXT NOT NULL,
  result TEXT NOT NULL,
  image_url TEXT,
  cta_label TEXT DEFAULT 'Markeer als gedaan',
  cta_url TEXT,
  sort_order INTEGER DEFAULT 0,
  created_by TEXT,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### tabel `daily_course_progress`

```sql
CREATE TABLE daily_course_progress (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id TEXT NOT NULL,
  course_id UUID NOT NULL REFERENCES daily_courses(id) ON DELETE CASCADE,
  completed BOOLEAN NOT NULL DEFAULT false,
  completed_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (user_id, course_id)
);
```

## 3. Slimme uitbreiding voor Basis / Pro

Als je per plan andere cursus-items wilt tonen:

* `basis` = alleen basis-items
* `pro` = basis + pro
* `admin` = alles beheren

Dan houd je dit veld aan:

```sql
plan TEXT NOT NULL DEFAULT 'basis'
```

Mogelijke values:

* `basis`
* `pro`
* `all`

Logica:

* gebruiker met basis ziet `basis` + `all`
* gebruiker met pro ziet `basis` + `pro` + `all`

## 4. Nog slimmer: sectoren meenemen

Voor OpenRegio is dit logisch:

* detailhandel
* horeca
* techniek
* agrarisch
* algemeen

Dan kan `sector` gewoon een tekstveld blijven, of later enum worden.

Voor nu:

```sql
sector TEXT NOT NULL DEFAULT 'algemeen'
```

## 5. Query voor actieve cursus-items

Dit is de kern. Alleen tonen wat nog binnen 7 dagen valt.

```sql
SELECT *
FROM daily_courses
WHERE status = 'published'
  AND posted_at <= now()
  AND expires_at > now()
ORDER BY posted_at DESC;
```

Nog beter: `expires_at` meteen zetten bij aanmaken. Dan hoef je niet steeds in code te rekenen.

## 6. Automatisch laten vervallen

* `posted_at = now()`
* `expires_at = now() + interval '7 days'`

## 7. Drizzle schema voor Replit

Als je Node + Drizzle gebruikt, dan zo:

```ts
import {
  pgTable,
  uuid,
  text,
  integer,
  boolean,
  timestamp,
  unique
} from "drizzle-orm/pg-core";

export const dailyCourses = pgTable("daily_courses", {
  id: uuid("id").defaultRandom().primaryKey(),
  title: text("title").notNull(),
  slug: text("slug").notNull().unique(),
  category: text("category").notNull(),
  sector: text("sector").notNull().default("algemeen"),
  plan: text("plan").notNull().default("basis"),
  status: text("status").notNull().default("draft"),
  postedAt: timestamp("posted_at", { withTimezone: true }).notNull(),
  expiresAt: timestamp("expires_at", { withTimezone: true }).notNull(),
  minutes: integer("minutes").notNull(),
  goal: text("goal").notNull(),
  action: text("action").notNull(),
  result: text("result").notNull(),
  imageUrl: text("image_url"),
  ctaLabel: text("cta_label").default("Markeer als gedaan"),
  ctaUrl: text("cta_url"),
  sortOrder: integer("sort_order").default(0),
  createdBy: text("created_by"),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
  updatedAt: timestamp("updated_at", { withTimezone: true }).defaultNow().notNull(),
});

export const dailyCourseProgress = pgTable("daily_course_progress", {
  id: uuid("id").defaultRandom().primaryKey(),
  userId: text("user_id").notNull(),
  courseId: uuid("course_id")
    .notNull()
    .references(() => dailyCourses.id, { onDelete: "cascade" }),
  completed: boolean("completed").notNull().default(false),
  completedAt: timestamp("completed_at", { withTimezone: true }),
  createdAt: timestamp("created_at", { withTimezone: true }).defaultNow().notNull(),
}, (table) => ({
  userCourseUnique: unique().on(table.userId, table.courseId),
}));
```

## 9. Backend logica voor ophalen

Pseudo:

```ts
const now = new Date();

const items = await db.query.dailyCourses.findMany({
  where: (course, { and, lte, gt, eq }) =>
    and(
      eq(course.status, "published"),
      lte(course.postedAt, now),
      gt(course.expiresAt, now)
    ),
  orderBy: (course, { desc }) => [desc(course.postedAt)]
});
```

## 10. Waarom dit beter is dan alleen `postedAt`

Omdat je anders elke keer dit moet rekenen:

* vandaag - postedAt < 7

Dat kan, maar `expiresAt` is cleaner. Dan kun je later ook:

* 3-daagse acties
* 14-daagse specials
* weekend boosts
* premium cursus langer zichtbaar

Dus strategisch is `expiresAt` slimmer.
